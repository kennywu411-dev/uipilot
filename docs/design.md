# UIPilot 设计说明

## 1. 要解决的问题

很多企业系统没有 API，只能靠人在网页上点：老 ERP、供应商门户、政务网站、内部 OA。这类工作过去靠 RPA 脚本，但页面一改脚本就坏。浏览器 Agent（Claude 的 `browser_toolset_20260801`）能看懂页面，适应性好很多，但能不能放心交给它，要看三件事：

1. **它能不能把事做对**：能否在页面上完成任务、发现结果不对；
2. **它会不会闯祸**：会不会删数据、乱跑到别的网站、把拿不准的事硬做完；
3. **值不值得**：一次任务花多少钱、多长时间，和人工、和传统脚本比怎么样。

UIPilot 用一个共用底座加两个应用，分别回答这三件事。

## 2. 结构

```
src/uipilot/
  browser.py     执行器：把 browser_toolset 的 31 个成员工具落到 Playwright；网络边界、不可逆操作拦截、确定性信号
  snapshot.js    可访问性树 + 稳定引用（ref 一旦发出不重排，导航后失效）
  agent.py       Agent 循环：toolset + 自定义工具、预算 / 轮数上限、计费、轨迹 JSONL
  erp/           靶子：模拟的老式进销存 ERP，14 个可开关的植入缺陷
  scout/         应用一：探索式测试 Agent（探索 → 复现 → 归并）+ 随机点击对照组
  entry/         应用二：单据录入 Agent + 24 张单据（18 张正常，6 张该转人工）
  evaluate.py    评测入口，总预算封顶
```

两个应用跑在同一个靶子上：测试 Agent 在"有缺陷"的 ERP 上找问题，录单 Agent 在"干净"的 ERP 上录单。

## 3. 关键设计决定

### 3.1 用 browser_toolset，而不是 computer_toolset

页面任务用浏览器工具集更合适：它同时提供截图坐标操作和可访问性树引用操作，不需要整台虚拟桌面。执行器自己实现，因为工具集是客户端工具，Anthropic 不托管浏览器。

### 3.2 三种观察方式做成配置，而不是三套代码

`vision`（只给截图）、`dom`（只给可访问性树）、`hybrid`（都给）只是 toolset `configs` 里开关不同的成员。这样对照实验只改一个变量。

### 3.3 安全边界放在执行器里，不靠提示词

- **网络边界**：`context.route` 拦截一切非被测源的请求；`/__admin` 评测接口对浏览器不可见；`navigate` 只接受 http(s) 和被测源。
- **不可逆操作**：每次点击前算出目标元素的文字（引用目标读元素本身，坐标目标用 `elementFromPoint`），命中"删除 / 作废 / 清空"等词时按策略处理：测试环境 `sandbox` 放行，录单 `protect` 拒绝并提示走 `escalate`。
- 理由：提示词只能"劝"，执行器能"拦"。同样的思路在 DataPilot 的行列级权限里用过：权限靠改写 SQL 强制执行，而不是靠提示词。

### 3.4 确定性信号 + 模型判断

执行器收集控制台报错、页面异常、HTTP 5xx、弹窗。测试 Agent 可以选择把这些信号附在工具结果里（`oracle_signals`），评测里做开 / 关对照：信号对"会报错的缺陷"有用，对"算错了但不报错"的业务缺陷没用，后者只能靠模型读懂规则。

### 3.5 测试 Agent 用"复现"压误报

探索 Agent 报的每条缺陷，都在全新重置的环境里交给另一个 Agent 只按报告步骤重做。复现不了的报告不计入结果。这对应真实团队里"QA 提单 → 开发复现"的流程，也是测试类 Agent 最常被诟病的误报问题的直接解法。

### 3.6 录单 Agent 的成功按数据库状态判定

不看 Agent 说自己做了什么，只看录完后数据库里多了什么：供应商、日期、对方单号、每行（编码、数量、单价）全部对上才算成功；陷阱单据必须"没有新单 + 调用了 escalate"才算成功；任何已有单据被删都判失败。

### 3.7 只追加历史

Opus 5.5 / Sonnet 5.5 的思考块和对话绑定，改写历史会让思考块失效。Agent 循环从不修改已发出的消息，只追加；控制上下文成本靠提示缓存（顶层 `cache_control`），而不是删旧截图。

### 3.8 模型负责读，代码负责判

- **录单的代码校验**（`entry/checks.py`）：模型先用 `record_document` 把单据原样登记，代码按税号在供应商主数据里精确查找、用 Decimal 重算合计、查重复单号，下结论“能录 / 必须转人工”；`finish` 时回读刚保存的采购单逐项比对。实验表明，这批单据上真正起作用的是“单据上有税号”这条信息，校验没有再提高正确率（docs/numbers.md 1.3），它的价值在可审计和兜底。
- **计算器工具**（`calc.py`）：测试 Agent 的复现阶段可以开启“核对期望值”，涉及金额必须调用它。让模型自己再算一遍挡不住模型之间相同的算术错误（问题日志 P14）。

### 3.9 外部项目适配

`scout/external.py` 让测试 Agent 跑在任意静态 Web 应用上：每个应用起一个独立的本地服务（独立的源，Agent 跑不到别处），规格书原文当业务规则，每次探索和复现都用全新的浏览器。没有植入清单，复现通过的报告用确定性脚本按真人操作复核（`scripts/verify_findings.py`）。

## 4. 评测设计

| 应用 | 数据 | 指标 | 对照 |
|---|---|---|---|
| 测试 Agent | 14 个植入缺陷分 A/B/C 三组 + 一轮无缺陷 | 复现确认后的检出率、误报数、被复现筛掉的报告数、单轮成本 | 随机点击；vision / dom / hybrid；信号开 / 关；Haiku / Sonnet / Opus |
| 录单 Agent | 24 张单据图片（三种版式） | 整单成功率、字段准确率、陷阱单转人工率、误转人工数、被拦截的危险动作、单张成本和耗时 | vision / dom / hybrid；Haiku / Sonnet / Opus |

缺陷与报告的对应由 Sonnet 5.5 判断，人工抽查后登记一致率。所有数字登记在 `docs/numbers.md`，写明运行目录。

## 5. 不做的

- 不接真实的第三方网站（安全与条款风险）；要接真实系统时，先在克隆的测试环境里跑。
- 不做通用 RPA 平台、不做录制回放编辑器。
- 不用 Claude 的输出训练其他模型（Anthropic 商业条款不允许）。
