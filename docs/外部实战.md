# 外部实战：TodoMVC

写于 2026-11-07。目标仓库 [tastejs/todomvc](https://github.com/tastejs/todomvc)，提交 `ff43b02`（2026-05-02，2.0 版）。

## 做法

- 被测对象：11 个官方实现：react、vue、svelte、preact、lit、javascript-es6、javascript-es5、web-components、jquery、backbone、mithril。每个实现单独起一个本地静态服务；每次探索和复现都用全新的浏览器，localStorage 为空。
- 业务规则：规格书 `app-spec.md` 的 Functionality 一节，原文交给 Agent。
- 流程：Haiku 5.5、Sonnet 5.5 各探索 1 遍，Opus 5.5 探索 3 遍（每个实现最多 60 轮）→ 每条报告由 Sonnet 5.5 在全新浏览器里复现 → 复现通过的报告，用 Playwright 确定性脚本按真人的操作方式逐条复核（`scripts/verify_findings.py`，不调用模型，每条都从空页面开始，用真实的点击和键盘事件）。
- 运行目录：`runs/external-haiku-20261107-000843`、`runs/external-sonnet-20261107-002656`、`runs/external-opus-20261107-004119`；复核的原始输出在 `runs/verify-*.txt`。

**三档模型合计去重后，复核成立的规格偏差共 15 处，分属 7 个实现，全部有 Agent 参与发现**（svelte 的“改成纯空格”Opus 和复核脚本各自发现）。在仓库的 issue 和 PR 里都没有搜到这些问题，已提交为 #2309–#2315。

| 实现 | 条款 | 偏差 | 发现者 | 官方测试为什么没抓到 |
|---|---|---|---|---|

| lit | New todo | 只输入空格也会新建空白待办 | Haiku、Opus | 同上 |
| lit | New todo | 新建时不 trim，首尾空格留在标签里 | Haiku、Opus | 同上 |
| web-components | New todo | 只输入空格也会新建空白待办 | Haiku、Opus | shadow DOM 实现，不在默认测试集里 |
| web-components | Clear completed button | 没有已完成条目时按钮仍显示 | Haiku、Sonnet、Opus | 同上 |
| web-components | Editing | 改成只有空格再回车，留下一条空白待办 | Opus | 同上 |

| svelte | Editing | 改成只有空格再回车，留下一条空白待办（空字符串正常） | Opus、复核脚本 | `should remove the item if an empty text string was entered` 只测了空字符串 |
| svelte | Editing | 编辑保存时不 trim，首尾空格被原样保存 | Opus | `should trim entered text` 断言用的是 `contain`，标签带着空格也能通过；localStorage 检查对 svelte 豁免 |
| svelte | Routing | 在某个筛选下刷新，地址栏不变，筛选按钮却回到 All | Opus | 官方测试里唯一刷新页面的是持久化用例，svelte 被豁免跳过；路由用例不刷新 |

**官方已知、不算新问题**：10 个实现刷新后数据丢失。规格书仍要求持久化，但 `cypress/e2e/spec.cy.js` 里写明“多数现代重写版只在内存里”，并对它们豁免了 localStorage 检查。

**不成立或不计入**：

- backbone 不支持 `#!/` 路由（Haiku）：规格只是允许用 `#!/` 代替 `#/`，并不要求两种都支持。
- web-components 计数文案带感叹号（Haiku）：规格书只给了示例文字，react 也这样写，不计入。
- Completed 筛选下全选框显示为勾选（Opus，web-components、react 有此行为）：规格写的是“所有待办都完成时勾上”，筛选状态下有两种理解；其余 5 个实现不勾。按保守原则不计入。
- 被复现阶段挡下的：Sonnet 的“react 清空后回车不删除”、Opus 的“mithril 全选只切换第一条”（出现过 2 次）。复核脚本也确认这两点是正常的。

## Opus 跑 3 遍的稳定性

Opus 3 遍合起来找到了全部 15 处。其中 10 处 3 遍都找到；web-components “改成纯空格”2 遍；lit 不 trim、svelte 编辑不 trim、web-components 失焦丢修改、mithril 删错条目这 4 处只在 1 遍出现。单遍分别找到 11、10、15 处，第 3 遍一遍就找全了，前两遍各漏掉 4、5 处。单遍结果波动大，多跑几遍取并集是值得的。

## 复核中的一次更正

lit 上 Haiku 报了“失焦不保存”，Sonnet 报了“按 Enter / 按 Esc 都退不出编辑”，3 条都通过了 Agent 复现。我最初用脚本复核时三种操作都正常，便判为“不成立”，还记下“复现 Agent 和探索 Agent 共享盲区”。后来 Opus 指出根因是“双击后编辑框没有获得焦点”，我按真人方式重测（双击后直接敲键盘）才确认：焦点停在页面上，按键全部无效。最初复核用的 `fill()` 会强制让输入框获得焦点，正好掩盖了这个缺陷。3 条报告改判为成立，详见问题日志 P13。

## 启示

1. **三档模型的发现互补**。Opus 找到的最多，也是唯一点出 lit 根因、发现 mithril 删错条目和 svelte 筛选问题的模型；Haiku 以 Opus 单遍 1/6 的花费找到 8 处，其中“lit 不做 trim”在 Opus 3 遍里只出现 1 次。
2. **Agent 能测官方测试工具测不到的地方**。lit 和 web-components 因为 shadow DOM 被排除在官方默认测试之外，Agent 通过浏览器工具集照样能操作，在这两个实现上找到了 8 处偏差。
3. **复核方法也要被审视**。确定性脚本不等于没有盲区：直接改值的捷径会绕过真实用户的操作路径。对 Agent 的报告，“我复核不出来”不等于“它是错的”。

## 已提交的 issue

2026-11-07 经本人同意，按实现分成 7 份提交到 tastejs/todomvc（提交前确认了仓库最新提交仍是 `ff43b02`，并逐条查重）： [#2309](https://github.com/tastejs/todomvc/issues/2309) react、[#2310](https://github.com/tastejs/todomvc/issues/2310) javascript-es5、[#2311](https://github.com/tastejs/todomvc/issues/2311) javascript-es6、[#2312](https://github.com/tastejs/todomvc/issues/2312) mithril、[#2313](https://github.com/tastejs/todomvc/issues/2313) lit、[#2314](https://github.com/tastejs/todomvc/issues/2314) web-components、[#2315](https://github.com/tastejs/todomvc/issues/2315) svelte。下面是提交前的草稿，正文以 GitHub 上的为准。

### 1. react: Escape does not leave editing mode, and the "discarded" edit is saved on blur

> **Spec** (app-spec.md, Editing): "If escape is pressed during the edit, the edit state should be left and any changes be discarded."
>
> **Steps** (examples/react/dist, commit ff43b02, Chromium)
> 1. Add a todo "buy milk".
> 2. Double-click it, change the text to "changed", press Escape.
> 3. Click the "What needs to be done?" input.
>
> **Expected**: after step 2 the item leaves editing mode showing "buy milk"; step 3 changes nothing.
> **Actual**: after step 2 the `<li>` keeps the `editing` class and the edit input stays visible; after step 3 the todo is saved as "changed".
>
> The Cypress test `should cancel edits on escape` only asserts the label text right after Escape, so it passes.
>
> Found with an AI browser-testing tool and verified with a Playwright script using real keyboard events.

### 2. javascript-es5: "Mark all as complete" is not kept in sync with the items

> **Spec** (Mark all as complete): "Make sure to clear the checked state after the 'Clear completed' button is clicked. The 'Mark all as complete' checkbox should also be updated when single todo items are checked/unchecked."
>
> 1. Add "a" and "b", tick both individually → toggle-all stays unchecked.
> 2. Use toggle-all to complete both, untick one → toggle-all stays checked; clicking it again un-completes everything.
> 3. Complete all, click "Clear completed", add "c" → toggle-all is checked although "c" is active.
>
> javascript-es6, jquery, vue and react behave as specified.

### 3. javascript-es6 (Modern JavaScript): new todos are prepended instead of appended

> **Spec** (New todo): "Pressing Enter creates the todo, appends it to the todo list, and clears the input."
> **Steps**: add "a", then "b". **Actual**: the list shows "b, a".
> The Cypress test `should append new items to the bottom of the list` would fail here; the app is not in the default `mainFrameworks` set, so it is not run by default.

### 4. mithril: deleting an item in the Active view removes a different, hidden item

> **Steps**: add "done-one", "keep-a", "keep-b"; complete "done-one"; switch to Active; delete "keep-a"; switch to All.
> **Expected**: "done-one" and "keep-b" remain.
> **Actual**: "keep-a" and "keep-b" remain; the hidden completed "done-one" was deleted. vue deletes the right item.

### 5. lit: edit input is not focused after double-click; whitespace-only and untrimmed input on create

> **Spec** (Editing): "When editing mode is activated it will hide the other controls and bring forward an input that contains the todo title, which should be focused (`.focus()`)." (New todo): "Make sure to `.trim()` the input and then check that it's not empty before creating a new todo."
>
> 1. Add "one", double-click it, type "X" and press Escape → focus stays on `<body>`, nothing is typed, and the item stays in editing mode (Enter and blur do nothing either).
> 2. Type three spaces and press Enter → an empty todo is created.
> 3. Type "  lead" and press Enter → the label keeps the leading spaces.
>
> `tests/cya.js` excludes lit because Cypress cannot pierce the nested shadow roots and notes that "the lit example itself is correct"; these cases suggest it is not.

### 6. web-components: whitespace handling, edits lost on blur, "Clear completed" visibility, unreliable double-click

> 1. Type three spaces and press Enter → an empty todo appears and is counted.
> 2. Add a normal todo → "Clear completed" is visible although nothing is completed (spec: "Should be hidden when there are no completed todos").
> 3. Double-click a todo, replace the text, click elsewhere → the change is discarded (spec: "The edit should be saved on both blur and enter").
> 4. Double-click a todo, replace the text with three spaces, press Enter → an empty todo remains instead of being destroyed.
> 5. Double-clicking a todo enters editing mode only intermittently (3 of 5 attempts in our run; 2 of 4 after leaving an edit by blur).

### 7. svelte: whitespace handling when editing; active filter not restored on reload

> **Spec** (Editing): "Make sure to `.trim()` the input and then check that it's not empty. If it's empty the todo should instead be destroyed." (Routing): "Make sure the active filter is persisted on reload."
>
> 1. Add "a" and "b"; double-click "a", replace the text with three spaces, press Enter → an empty todo remains (an empty string is handled correctly).
> 2. Double-click a todo, replace the text with "  spaced  ", press Enter → the label keeps the spaces (vue, react and preact trim it).
> 3. Click "Completed", reload → the URL is still `#/completed` but the "All" filter is highlighted. vue keeps "Completed" selected.
