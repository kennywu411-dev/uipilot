# UIPilot：让 Agent 在没有 API 的网页系统里干活

很多企业系统没有 API，只能靠人在网页上点：老 ERP、供应商门户、内部 OA。UIPilot 用 Claude 的浏览器工具集（`browser_toolset_20260801`）搭了一个**共用底座**，在上面做了两个应用，并在同一个靶子系统上做了对照评测：

- **探索式测试 Agent**：读业务规则，在页面上操作，找出“结果不对”的缺陷；每条报告在重置后的环境里由另一个 Agent 复现，压掉误报。
- **单据录入 Agent**：看供应商单据的扫描件，在老 ERP 里录采购单；拿不准的（供应商或商品不存在、金额自相矛盾、单号已录过）转人工；不允许删除任何数据。

## 结果（2026-11-06，详见 [docs/numbers.md](docs/numbers.md)）

**测试 Agent**：14 个植入缺陷，其中 12 个不会报错，只能靠读懂业务规则才能发现。

| | 检出率（复现确认） | 误报 | 每组成本（估算） |
|---|---|---|---|
| Haiku 5.5（截图 + 页面结构，2 遍） | 89.3% | 0 | $0.25 |
| Haiku 5.5 只看截图 / 只看页面结构 | 92.9% / 92.9% | 0 | $0.33–0.34 |
| Sonnet 5.5 | 92.9% | 0 | $1.00 |
| Opus 5.5 | 92.9%（人工复核后） | 0 | $1.68 |
| 随机点击（对照组） | 0% | — | $0 |

- 所有“没对上植入清单”的确认报告，经人工逐条复核，都是靶子**真实存在的缺陷**：单价三位小数被静默舍入、采购单搜索区分大小写。这两个都不是我植入的，是 Agent 自己找出来的，已修复。
- 评判模型（Sonnet 5.5）和人工复核的一致率是 99/100。

**录单 Agent**：难题集 20 张单据，每张 6–10 行明细、低分辨率扫描，陷阱都是“看着像”的类型。

| | 整单成功 | 误转人工 | 录错 | 单张成本（估算） |
|---|---|---|---|---|
| Haiku 5.5 | 85–90% | 2–3 | 0–3 | $0.005–0.007 |
| Sonnet 5.5 | 95% | 0 | 1 | $0.099 |
| Opus 5.5 | 95% | 0 | 1 | $0.183 |

- 基础集（24 张）所有配置都是 100%，已经饱和，只有成本拉得开（Opus 是 Haiku 的 30 倍）。
- Haiku 在模糊扫描上会看错字（“英规”读成“美规”），但看错后选择转人工，没有把错误数据录进系统。
- 三档模型都栽在同一张单上：“深圳市华强电子**科技**有限公司”被当成系统里的“深圳市华强电子有限公司”录入。这类风险靠提示词挡不住，需要确定性校验，例如比对税号。
- 所有运行中，已有单据被删除的次数为 0。

## 设计要点（详见 [docs/design.md](docs/design.md)）

- **安全边界放在执行器里，不靠提示词**：网络层只放行被测系统；评测接口对浏览器不可见；录单时，会删数据的请求在网络层拦截；按钮文字检查只用来提前提示，并对不提交数据的纯页面按钮放行（问题日志 P10）。
- **三种观察方式是配置开关**：只看截图、只看页面结构、两者混合，只改 toolset 的 `configs`，对照实验只差一个变量。
- **用复现压误报**：探索报的每条缺陷，都在全新环境里只按报告步骤重做一遍；报告步骤必须能从初始数据独立复现。
- **结果按数据库状态判定**：录单是否成功只看录完后数据库里多了什么，不看 Agent 自己怎么说。
- **历史只追加**：Opus 5.5 / Sonnet 5.5 的思考块和对话绑定，循环从不改写已发出的消息，靠提示缓存控制成本。

## 结构

```
src/uipilot/
  browser.py    browser_toolset 31 个成员工具的 Playwright 执行器 + 网络边界 + 删除拦截 + 报错/5xx 信号
  snapshot.js   可访问性树与稳定引用（已发出的引用不重排，处理了 cloneNode 复制引用的问题）
  agent.py      Agent 循环：预算、轮数上限、计费、轨迹 JSONL、内容过滤与工具误标的容错
  erp/          靶子：“宏远进销存 V3.2”，14 个可开关的植入缺陷
  scout/        测试 Agent（探索 → 复现 → 评判）与随机点击对照组
  entry/        录单 Agent、单据生成器（基础集 24 张、难题集 20 张）
  evaluate.py   评测入口：总预算封顶、单轮出错不影响整组、--resume 续跑
docs/           设计说明、数字登记表、问题日志（11 条，每条有现象/原因/修法/验证）
```

## 运行

```bash
uv sync
uv run playwright install chromium
uv run pytest                       # 32 个测试，不调用 API
```

需要在项目根目录的 `.env` 里写 `ANTHROPIC_API_KEY=...`（已在 `.gitignore` 里）。

```bash
uv run python scripts/smoke.py hybrid claude-haiku-5-5        # 最小任务，约 $0.001
uv run python -m uipilot.evaluate entry --set hard --model claude-haiku-5-5 --total-budget 1
uv run python -m uipilot.evaluate scout --model claude-haiku-5-5 --groups A clean --total-budget 2
uv run python -m uipilot.evaluate monkey --steps 300 --seeds 1 2 3
uv run python scripts/report.py     # 汇总 runs/ 下的结果
```

## 局限与下一步

- 靶子和缺陷都是自己做的，能说明方法有效，不代表在真实系统上的效果。下一步：在开源 Web 应用的本地副本上跑测试 Agent，以维护者确认的缺陷数作为外部证据。
- 测试 Agent 每种配置大多只跑了 1 遍，配置之间差一两个缺陷，不下“谁更好”的结论。
- 录单要加确定性校验（税号比对）来挡“名字相近的另一家公司”，并加一个“已录入但需复核”的结论，代替只写在备注里的提醒。
- 成本是按价目表估算的，和 Console 账单还有差额没核清（见 numbers.md 开头）。
